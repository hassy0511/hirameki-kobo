## 3. 出題品質の基準(この文書の核心)

今回、実際に生成された全132ステージ×8問を1問ずつ測って確立したもの。
**すべて自動検査できる形にすること。書いてあるだけでは守られない。**

### 3.1 盤面は「問題の状態」を見せる。「答えの形」を見せない

いちばん重い基準。これを破ると、計算問題が「ただタップして終わる」ものになる。

実際に起きていた例:

- 数の分解の盤面が、置き場に丸を「たりない数」ちょうど置いていた
  → 全部タップすれば必ず正解。いくつ足りないか考える場面が消える
- 足し算の合流盤面が、タップできる数を答えそのものに設定していた
  → 「あわせると いくつ？」が全部タップで正解になる
- 等分の盤面が、確定前に「ぴったり おなじ！」と表示していた
  → 表示が変わるまで動かせば当たる。割り算ではなく当てもの遊び
- 面をスタンプする問題の盤面に、答えの語が文字で出ていた

**検査**:
- タップできる要素の数が正解と一致してはいけない(「ぜんぶ とる」型を除く)
- 確定前に正誤・過不足を示す表示を出してはいけない
- 盤面に答えの語を文字で描いてはいけない

### 3.2 答えを問題文・操作説明に書かない

「30この部品を10こずつにする。1ケース分を選ぼう」は、問題文が答え(10)を先に言っている。
「一人ぶんは？」の操作説明が「2こ えらんで「けってい」」も同じ。

**検査**: 計算のステージで、正解の数が問題文・操作説明に現れる割合の上限を決める。
表現・測定の課題(「4この えグラフを つくろう」「14cmまで光らせよう」)は対象外。
数を与えることが課題の本質だから。

### 3.3 問題文の動詞と操作を一致させる

「6この まるから 4こ とろう」と書いてスライダーを出さない。
「回路をつなごう」と書いて実体がただの4択、もダメ。

**検査**: 動詞→許可される操作の辞書を持ち、不一致を落とす。
操作説明はkindごとの定型文で上書きせず、何をすればよいかが分かる文にする。

### 3.4 ステージ名が約束したことを問う

「のこりは いくつ？」というステージで、子どもが一度も残りを答えないことが起きていた。
取る操作(問題文の数をタップ)だけで8問が終わっていた。

**対処**: 導入2問で具体物の操作、残り6問で結果を答える。
時計の「読む⇄合わせる」と同じ相補ペアとして扱う。

### 3.5 誤答は誤概念から作る

正解±1・±2のランダムでは、何を間違えたか分からない。

- 足し算 → 片方の数だけ答える／引いてしまう／1ずれ
- 引き算 → たしてしまう／引く数・引かれる数をそのまま答える
- 位取り → 十と一の取り違え／十の位を1こ多く数えた／ばらだけ答えた

**検査**: 誤答に0を出さない(丸が見えているのに0は不自然。0を学ぶステージを除く)。
小1に「2−7」のような答えの出ない式を見せない。
選択肢の型を揃える(式・裸の数値を混ぜない)。

### 3.6 同じ問題を続けない

飾りの違い(並べ方など)を「別の問題」と判定していたため、
最初のステージが 2個→2個→3個→3個 と同じ問題を繰り返していた。

**検査**:
- 学習内容の同一性は「何を問い、答えが何か」で判定する。見た目の飾りを含めない
- 画面が同じ問題を一度のステージで二度出さない
- 直前と同じ学習内容・同じ答えにしない
- 教材が有限なステージ(1〜5を数える等)は8問すべて別内容にできない。
  「使い切るまで再利用しない」「3度は繰り返さない」を契約にする
- 遊び直したときに文型が変わること。数だけ変えて文が固定だと「さっきと同じ」に見える

### 3.7 文章の作法

- 対象学年が読める表記に統一する。**問題文だけでなくヒントと解説も。**
  つまずいた子がいちばん読むのはヒント。そこが漢字だらけでは意味がない
- 漢字をかなに直すときは分かち書きを保つ。
  「みじかいはりは10とつぎのかずの間だよ」は元より読みにくい
- 場面問題はキャラクター名を前置することではない。数の意味が立ち上がる一文を作る。
  場面として書けない問題には何も前置しない
- 解説は式だけにしない。何をどうしたらそうなったかを式の前に置く
- 問われ方と答え方を食い違わせない
  (「どちらが多い？」の答えが「おなじ」、二択で聞いて第三の答え)
- ステージ名と同じ文字列を問題文に前置しない(画面に二重に出る)

### 3.8 つまずいた子への支援

- 一度目の誤答は具体的なヒント、二度目は正解を含む説明を出して次へ進める
- ヒントは盤面から決める。ビルダーを共有する別ステージの言い回しが混ざらないようにする
- ヒントに答えをそのまま書かない

### 3.9 確定の文法を統一する

選んだ瞬間に確定する操作と、「けってい」を押すまで確定しない操作を混ぜない。
同じタップが問題ごとに意味を変えると、いちばん土台の文法が崩れる。
学年でも変えない。

**注意**: 選択状態は問題の初期値と別に持つ。
初期値を選択済みとして扱うと、何も選んでいないのに誤答が選ばれて見え、確定も押せてしまう。

## 5. 実装前に決めること

1. **出題ロジック(型)と素材データ(中身)を分ける。**
   学年やステージの追加がデータ追加だけで済む形にする
2. **出題生成は純関数にし、乱数は注入する。**
   同じseedから同じ問題が出ること。今回、注入していない抽選が1か所混ざっていて、
   同じseedで違う問題が出ていた
3. **第3章をユニットテストの不変条件として最初に書く。**
   1000問生成して全部満たすことを検査する。実装より先に書く
4. **1ステージ1中心操作。** 操作を変えてよいのは課題が変わるときだけ。
   「読む⇄作る」のような相補ペアに限る
5. **配信の版番号を上げる仕組みを最初から入れる。**
   今回、出題を直したのに版番号が据え置きで、既存の利用者に古いファイルが配られる状態だった。
   テストは版番号を直書きせず、index と Service Worker が同じ番号を指すことを検査する
